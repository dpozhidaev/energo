# Уведомления об отключениях в Песках

Python 3.11+. Проверка всех страниц Рощинского РЭС по исходной ссылке пользователя: https://rosseti-lenenergo.ru/planned_work/?reg=344&res=370.

Программа ищет поселок Пески в Выборгском районе, включая общие записи на несколько поселков — сам посёлок интересует, а не остальной состав такой записи. Исключает завершившиеся отключения; включает будущие и продолжающиеся. На каждую актуальную запись отправляет отдельное сообщение в Telegram (время по Москве, комментарий с сайта, ссылка на источник; адрес в сообщении — только строки с улицами по Пескам, если они указаны на сайте (например «п Пески, ул Пихтовая»), иначе общий «пос.Пески, Выборгский район»; остальные посёлки общей записи сайта никогда не выводятся). Без записей молчит. Каждая запись (`record_id` с сайта) отправляется только один раз — повторно уже отправленную программа не пришлёт, даже если на следующий день она всё ещё актуальна. Для этого в `sent.json` хранятся последние 10 отправленных `record_id`; файл коммитится обратно в репозиторий самим workflow после отправки (см. шаг `Save sent-notifications state`). По умолчанию используется Telegram; можно выбрать отправку по SMTP.

Сайт закрыт для адресов за пределами РФ (DDoS-Guard: «the website owner has restricted access from your current IP address»), а раннеры GitHub Actions расположены не в России. Поэтому при недоступности сайта напрямую программа автоматически подбирает рабочий российский прокси (HTTP/SOCKS4/SOCKS5) из открытых бесплатных списков и повторяет проверку через него — см. раздел «Подбор прокси» ниже.

## Параметры программы

Все параметры находятся в `config.json`:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `check_time` | `09:00` | Время проверки по Москве, HH:MM |
| `settlement` | `Пески` | Название без «п.» / «поселок» |
| `district` | `Выборгский` | Название без «район» |
| `region_id` | `344` | Код региона в фильтре сайта |
| `res_id` | `370` | Рощинский РЭС; пустая строка — все РЭС региона |
| `channel` | `telegram` | `telegram` или `email` |
| `telegram_chat_id` | пусто | Получатель; необязателен — Secret `TELEGRAM_CHAT_ID` имеет приоритет и обычно достаточен |
| `email_to` | пусто | Получатель при выборе email; задайте явно в `config.json`, если используете `channel: "email"` |

ID Telegram нельзя определить по почте; получите его после `/start` по инструкции ниже. Токены и SMTP-пароль задаются через окружение / GitHub Secrets. `telegram_chat_id` и `email_to` в `config.json` по умолчанию пустые — заполняйте только если не хотите держать значение в Secrets/переменных окружения.

При смене поселка проверьте район, регион и РЭС: старый фильтр может исключить новый поселок. Для поиска по всему региону задайте `res_id` пустой строкой.

После изменения времени выполните:

```sh
.venv/bin/python monitor.py --write-schedules
```

Команда обновляет `.github/workflows/check.yml` и `deploy/peski-monitor.timer`. Закоммитьте их вместе с `config.json`. **GitHub читает расписание из YAML: изменение только JSON не меняет время запуска.** Тест обнаруживает расхождение. На VM скопируйте обновленный timer, выполните `sudo systemctl daemon-reload` и `sudo systemctl restart peski-monitor.timer`.

`python monitor.py` делает одну проверку сразу; расписание обеспечивает Actions или systemd. Свой файл можно передать через `--config /path/to/config.json`.

Для почты выберите `channel: "email"`, задайте `email_to` в `config.json` и Secrets `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`. Используется SMTP over TLS, `SMTP_PORT` по умолчанию 465, `SMTP_FROM` по умолчанию совпадает с SMTP_USER. При необходимости используйте пароль приложения почтового провайдера. Проверка выбранного канала: `python monitor.py --test-message`. Автоматического переключения с Telegram на email нет.

## Установка и проверка

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python monitor.py --dry-run
.venv/bin/python -m unittest discover -s tests -v
```

`--dry-run` загружает настоящий сайт без отправки сообщений.

## Telegram

1. Откройте [BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username. Сохраните токен.
2. Откройте своего бота, нажмите Start или отправьте `/start`. Бот не может первым начать личный диалог.
3. В терминале bash введите токен скрытым вводом:

```bash
read -r -s -p 'Telegram token: ' TELEGRAM_BOT_TOKEN
export TELEGRAM_BOT_TOKEN
printf '\n'
.venv/bin/python monitor.py --chat-id
```

4. Задайте полученный числовой ID своего чата и проверьте доставку:

```sh
export TELEGRAM_CHAT_ID='ВАШ_ЧИСЛОВОЙ_ID'
.venv/bin/python monitor.py --test-message
.venv/bin/python monitor.py
```

Если ID не найден, отправьте боту новое сообщение и повторите команду. Если ID несколько, выберите свой чат. Токен храните в Secrets, не в коде и не в публичной переписке.

## Бесплатное размещение: GitHub Actions (рекомендуется)

Отдельная виртуальная машина не нужна. Создайте личный **private** репозиторий `peski-monitor` на GitHub Free. В тариф входят 2000 минут стандартных Actions в месяц; короткий ежедневный запуск обычно занимает небольшую часть лимита. Лимит общий с другими проектами аккаунта. Если подключена оплата, задайте бюджет с остановкой платного превышения; без способа оплаты задания останавливаются после исчерпания квоты.

1. Загрузите содержимое этой папки в корень репозитория, включая скрытую папку `.github/workflows/` и `certs/`.
2. В Settings → Secrets and variables → Actions создайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
3. В Actions выберите `Peski daily outage check` → Run workflow. Убедитесь, что запуск зеленый. Если есть актуальные записи, должна прийти сводка. Актуальных записей может не быть неделями — чтобы проверить именно доставку в Telegram/email из самого Actions, поставьте галочку `test_message` (короткое подтверждение) или `sample_message` (пример настоящего уведомления об отключении текущим форматом и текстом, `--sample-message`).
4. Workflow должен находиться в основной ветке. Расписание уже настроено: каждый день в 06:00 UTC = 09:00 МСК.
5. В настройках уведомлений GitHub включите сообщения о неуспешных Actions. Проверяйте журнал запусков и Billing → Usage.

GitHub не гарантирует запуск точно в 09:00: возможны задержки и пропуски при нагрузке. В публичном репозитории стандартные runners бесплатны, но расписание отключается после 60 дней без активности. Поэтому здесь рекомендуется закрытый репозиторий в бесплатном лимите.

Доступность сайта с облачного runner необходимо проверить первым запуском: локальная проверка не гарантирует доступность из другой страны. Если прямой доступ заблокирован, программа сама подберёт прокси (см. «Подбор прокси» ниже); при этом ручной `workflow_dispatch` с `dry_run=true` всё равно полезен для проверки, что сам процесс и тесты проходят.

## Подбор прокси

При недоступности сайта напрямую (`collect_with_fallback` в `monitor.py`) программа:

1. Загружает кандидатов из открытых бесплатных списков — приоритетно [monosans/proxy-list](https://github.com/monosans/proxy-list) (обновляется автоматически, содержит геолокацию и протокол каждого узла — HTTP, SOCKS4 или SOCKS5), с добавлением ProxyScrape и Geonode как резервных источников HTTP-прокси.
2. Оставляет только узлы с `country.iso_code == RU`, сортирует по измеренной задержке.
3. Параллельно проверяет кандидатов настоящим запросом к сайту (с той же проверкой сертификата, что и в `certs/`) и берёт первый, вернувший таблицу отключений, а не блокировку.
4. Использует найденный прокси для всех страниц текущей проверки и больше никуда не сохраняет его — на следующий день подбор повторяется заново.

Это бесплатный best-effort вариант: открытые списки прокси очень нестабильны, и часть узлов не работает или сама блокируется сайтом как известный прокси/VPN. Если за разумное время (десятки параллельных проверок) не нашёлся ни один рабочий адрес, процесс завершается ошибкой и, как и при любой другой ошибке проверки, пытается отправить предупреждение в Telegram (см. «Ошибки и безопасность соединения»). Если нужна более стабильная доставка, замените `fetch_candidate_proxies` на платный ротируемый российский прокси (большинство провайдеров дают единый эндпоинт вида `host:port` с логином/паролем в переменных окружения) — остальная логика подбора и проверки изменений не требует.

Для SOCKS4/SOCKS5 требуется пакет `PySocks` (уже добавлен в `requirements.txt`).

## Вариант с бесплатной виртуальной машиной

Кандидат — [Oracle Cloud Always Free](https://www.oracle.com/cloud/free/). Регистрация, верификация и наличие свободных ресурсов зависят от региона и аккаунта; получение VM не гарантировано. Используйте только ресурсы с пометкой Always Free, не пробные платные ресурсы. Oracle вправе изъять простаивающую бесплатную VM, поэтому для легкого ежедневного задания этот вариант менее удобен.

Программа готова для Ubuntu/Debian. После создания VM скопируйте проект в `/opt/peski-monitor`:

```sh
sudo apt-get update
sudo apt-get install -y python3-venv ca-certificates tzdata
sudo useradd --system --home /opt/peski-monitor --shell /usr/sbin/nologin peski
sudo python3 -m venv /opt/peski-monitor/.venv
sudo /opt/peski-monitor/.venv/bin/pip install -r /opt/peski-monitor/requirements.txt
sudo install -m 600 /dev/null /etc/peski-monitor.env
sudo nano /etc/peski-monitor.env
```

Запишите в env-файл:

```ini
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_CHAT_ID=ваш_числовой_id
```

Подключите таймер:

```sh
sudo cp /opt/peski-monitor/deploy/peski-monitor.service /etc/systemd/system/
sudo cp /opt/peski-monitor/deploy/peski-monitor.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start peski-monitor.service
sudo journalctl -u peski-monitor.service -n 50
sudo systemctl enable --now peski-monitor.timer
systemctl list-timers peski-monitor.timer
```

Таймер использует Europe/Moscow независимо от часового пояса VM. После простоя выполняется пропущенная проверка. Не включайте одновременно VM и Actions, иначе будут дубли (в том числе потому, что `sent.json` у каждого из них свой — на VM он просто лежит на диске, в Actions коммитится в репозиторий). Наблюдение за доступностью самой VM нужно настраивать отдельно.

## Ошибки и безопасность соединения

При недоступности сайта или изменении таблицы процесс завершается с кодом 1 и пытается отправить предупреждение в Telegram. Если Telegram недоступен или планировщик вообще не запустил процесс, такого предупреждения не будет. Отправка в Telegram автоматически не повторяется: неоднозначный сетевой ответ может привести к дублям. Получение страницы повторяется при временных ошибках.

У сайта российская цепочка сертификатов. В `certs/russian_trusted_root_ca.pem` включен публичный корневой сертификат, загруженный по HTTPS из [официального источника](https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt). Он используется только для запросов к Ленэнерго. Системное хранилище не изменяется, Telegram использует стандартную проверку TLS. Проверка сертификатов не отключается. Если цепочка изменится, обновите сертификат из [официального источника](https://www.gosuslugi.ru/crt).

Монитор отслеживает опубликованные плановые работы, не аварии. Отсутствие записи не гарантирует наличие электричества.
